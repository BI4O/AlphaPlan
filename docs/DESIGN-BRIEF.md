# 给设计 AI 的 prompt（复制下面整段）

---

你是一位擅长「金融数据界面 + 编辑式排版」的视觉设计师。请重新设计一个单页 Web 界面。

**项目：AlphaPlan** —— 一个可审计的 AI 基金经理。
核心主张：**「我们不承诺 AI 赚钱，我们承诺它的每一个决定你都能自己算一遍。」**

每 10 分钟，三个 AI agent（看多 / 看空 / 风控）各自给出目标仓位，一个 judge 裁决，
产出一份 JSON「计划」文件。文件的原始字节哈希被写进区块链。任何人可以拿文件自己算一遍哈希，
对得上就证明这个决定没被事后篡改。

---

## 必须保留的 5 个内容块（不能删、不能合并）

| 块 | 内容 | 视觉重点 |
|---|---|---|
| **A. 保真度角标** | 固定顶部一行：「L2 · 真实链路 · 真交易 · 签名方是本地 CLI，不是 DON」 | 必须永远可见（sticky）。这是诚实边界，不是免责声明 |
| **B. 辩论 → 裁决** | 3 张 agent 卡（看多/看空/风控，各含：目标仓位 bps、信心 0–1、一句理由），下方 1 张 judge 裁决卡（最终仓位、与算术平均的偏离、理由） | 叙事核心：三个意见分歧，judge 不取平均 |
| **C. 执行链路图** | 7 节点横向流程图：CRON 触发 → 链上读取 → HTTP 取计划 → KECCAK 哈希 → AI 共识 → 门禁 → 写链。每个节点可点开，里面每个数字带一枚来源标签：**链上 / 计划文件 / 规范 / 推断 / 未采集** | 最重要的设计难点：要让「来源标签」看起来是信息，不是装饰 |
| **D. 哈希自验** | 拖入文件 → 浏览器算 keccak256 → 与链上哈希比对 → 显示 ✓ 或 ✗（两边哈希都要显示） | 全页最高潮的一格。要让人想按下去 |
| **E. 金库 + 计划历史** | 金库 5 项数字（NAV / 份额价格 / 现金 % / WETH % / 总份额）；历史分两条流：「策略交易」和「流动性调整（非计划交易）」，另有一个对账小结（未解释的持仓变化必须是 0） | 数字密度最高的一块 |

## 现有设计系统（必须遵守）

**品牌气质：** 克制、可信、有判断力、亲密、不喧哗。
像私人银行的年报，不像科技产品落地页。**不要**加密货币 / Web3 视觉语言。

**色彩（只有 7 个角色，全部给死）**

| 角色 | Hex | 用途 |
|---|---|---|
| Paper 纸面 | `#faf8f3` | 页面底色，大面积留白是主色 |
| Linen 亚麻 | `#f2ece5` | 卡片 / 面板托底，必须配 1px Taupe 描边 |
| Ink Navy 墨蓝 | `#1e253d` | 正文、标题、金额 |
| Ash 灰 | `#6b6674` | **仅**次级文字、元信息 |
| Taupe 描边 | `#dbd3cb` | 1px 分隔线与卡片描边 |
| Quiet Indigo | `#42508c` | 主操作、焦点环、图表主线 |
| Oat 燕麦 | `#a7917e` | **只做装饰层**（标签底、下划线），其上必须压墨蓝文字 |

状态色：success `#40614d` / warning `#7f5b30` / error `#86463a`

**字体**
- 标题与修辞句：Newsreader（衬线，500–600，字距 −0.01em）
- 界面与正文：Inter（400–600，16px 起，行高 1.6）
- 金额 / 代码 / 时间戳：IBM Plex Mono（tabular-nums，数字列右对齐）

**版式规则**
- 8px 基线网格，4px 微步进，区块节奏 24 / 32 / 48 / 64
- 圆角 8px，描边 1px，**用描边不用阴影**（只有浮层允许一层柔和阴影）
- 全屏只允许一枚实心主按钮（Indigo），同屏不出现两个同等实心按钮
- 层级靠字重、字号、留白 —— **不要靠把正文调灰**
- 金额与单位必须 nowrap 绑定，数字绝不孤行
- 图表取色顺序固定：Indigo → Ash → Oat
- 正负值同时用正负号与颜色表达，不单靠颜色

## 现在的版本为什么难看（请针对性解决）

1. **页面被灰色淹没**：全站 73 处用灰（`text-ash`），只有 22 处用墨蓝。设计规范明确写了「正文不要调灰」，实现违反了它自己的规范。结果是一整页没有一处是"实"的，读完没有落点。
2. **14 种随手写的字号**（9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 14 / 15 / 19 / 22 / 26px）。设计系统只给了 6 档（44 / 36 / 30 / 24 / 20 / 16 / 14），实现绕过了它。这是"丑"的最大来源 —— 看起来像终端日志，不像排版过的页面。
3. **每块长得一样**：所有区块都是 `1px 描边 + 亚麻底 + 8px 圆角 + 上分隔线 + 48px 内边距`。5 个块视觉权重完全相同，眼睛不知道该先看哪。
4. **单栏 1024px 到底**：所有内容排成一条竖线，没有一个地方是"被设计过的"。
5. **完全没用图像**：项目里有一张情绪板（暖白纸面、亚麻、木桌、静物特写风格），一个字节都没用上。
6. **数据密度处理得糟**：最大的数字（仓位 bps、NAV）和最小的字（10px 元信息）挤在同一个卡片里，没有尺度对比，也没有呼吸。

## 请你交付

1. **一套排版骨架**：5 个块各自的视觉权重、栅格、留白节奏。说明哪一块是"主角"，其余的如何退后。
2. **明确打破单栏**的做法：哪里该用双栏 / 非对称栅格 / 满宽出血，为什么。
3. **字号与灰度的重新分配**：只在 6 档字号里取值；指出哪些地方现在被错调成了灰色、应该恢复墨蓝。
4. **B 块（辩论）的具体设计**：3 个分歧意见 + 1 个裁决，这是叙事核心，现在的三张等宽卡片没有把"分歧"讲出来。
5. **C 块（7 节点链路图）的具体设计**：这是全页最难的 —— 7 个节点 + 每节点多字段 + 5 种来源标签。请给出它在中屏和窄屏的形态。
6. **D 块（哈希自验）的具体设计**：要让人有"我想按一下试试"的冲动，但视觉上必须克制，不能变成营销 CTA。
7. 如果认为品牌气质（私人银行年报）与产品（链上可审计 AI）之间存在张力，**直说**，并给出取舍建议。

**输出格式：** 先给一段 200 字以内的设计判断（哪里最该改），再给逐块方案，最后给一版可直接落地的 Tailwind 类名建议（项目用 Tailwind v4 + 语义 token：`bg-paper` / `bg-linen` / `text-ink` / `text-ash` / `border-rule` / `text-indigo` / `text-oat` / `font-display` / `text-display` / `text-h5` / `text-body` / `text-meta`）。

**不要做的事：**
- 不要加渐变色、发光、玻璃拟态、卡片阴影堆叠
- 不要用紫色 / 彩虹 / 霓虹
- 不要画 K 线图、金币、机器人图标
- 不要打字机效果 / 数字滚动动画 / 骨架屏呼吸灯
- 不要改文案。文案已经定稿，只改视觉
- 不要引入新字体或新色值
